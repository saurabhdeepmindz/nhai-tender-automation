NHAI Tender Automation - Demo URLs

Quick reference for the customer demo. Run start-all.bat first, then use this page to jump straight to any screen.

Customer Demo Frontend screens (http://localhost:3000)
Screen URL Purpose
Home http://localhost:3000 Landing page with links to the vendor/admin apps and the static design-preview mockups.
Login http://localhost:3000/login Single sign-in screen for both vendor and admin demo accounts; redirects to the matching dashboard on success.
Vendor: vendor@example.com / password123
Admin: admin@nhai.gov.in / admin123
Vendor Dashboard http://localhost:3000/vendor/dashboard Vendor's home screen: RFP list (with search/filter), Total RFPs / Queries Submitted / Pending Queries stat cards (each clickable), and Recent Queries.
Vendor Query Submission http://localhost:3000/vendor/query-submission Form for a vendor to submit a new pre-bid query against an RFP.
Vendor Query History http://localhost:3000/vendor/query-history List of a vendor's submitted queries and their status; reached from the dashboard's stat cards or an RFP's "View" action.
Admin Dashboard http://localhost:3000/admin/dashboard Central hub for the admin side, with a card per admin feature so URLs never need to be memorized.
Admin - Historical Data http://localhost:3000/admin/historical-data Upload and manage historical RFP data used to train/seed the query-matching corpus; shows the historical vs. live RFP split and upload history.
Pre-bid Query Workflow (the key AI demo screen) http://localhost:3000/prebid-query/workflow Shows the AI workflow execution for a submitted query: the generated response plus a "Similar Historical Queries" table with confidence scores, matched against previous RFPs' pre-bid query responses. This is the screen shown in the Jan/Feb customer demo.
Pre-bid Query Management http://localhost:3000/admin/prebid-queries Admin workspace to review/finalize pre-bid query responses: filter and search, compare AI response against past RFP reference/response, edit and save the final admin response, and update status per-row or in bulk.
Technical Service health & API docs (not for the customer demo)
Service URL Purpose
Backend API base http://localhost:3001/api NestJS REST API root that the frontend calls (auth, vendors, queries, historical data, prebid-query workflow).
Historical Data Service docs http://localhost:8005/docs FastAPI Swagger UI for the Python service that ingests and stores historical RFP documents.
History Retriever docs (Screen 7) http://localhost:8000/docs FastAPI Swagger UI for the RAG service that retrieves relevant historical content from ChromaDB.
Chief Engineer docs (Screen 8) http://localhost:8001/docs FastAPI Swagger UI for the agent that runs the query-matching workflow and computes confidence scores.

Generated for use alongside start-all.bat / stop-all.bat in this same folder. Service status and this URL list are also written to ..\logs\startup-summary.log on every run. If a link doesn't load, check that the corresponding service actually came up (see the summary log or that service's own log under ..\logs\).
