01

Executive Summary

Every road-project tender draws pre-bid queries from vendors — many of them near-duplicates of questions NHAI has already answered in a previous RFP. Today that matching is manual: an engineer re-reads old corrigenda and reply documents to check whether a question has a precedent. This system automates that first pass.

A vendor's query is automatically compared, using AI, against a searchable archive of previously answered pre-bid queries and historical RFP documents. The system proposes a draft reply and shows exactly how confident it is and which past answer it drew from. No reply reaches a vendor without a human officer reviewing and approving it — the AI drafts, NHAI decides.

Speed

Minutes, not days

Draft answers with sourced precedent are ready for review as soon as a query is submitted, instead of an officer searching past tenders by hand.

Traceability

Every draft is sourced

Each AI answer carries a confidence score and a link back to the specific historical query/response it was built from.

Control

Officer has final say

An authorised reviewer can accept, edit, or replace the AI draft with a different historical precedent before anything is published.

04

Inside the Chief Engineer Agent

Step 4 of the lifecycle above — "AI Drafts a Response" — is itself a six-step pipeline. This is the core of the system's retrieval-augmented generation (RAG) design.

Screen 7

History Retriever Agent

Owns the historical RFP / corrigendum / Q&A document corpus. Splits uploaded documents into chunks, embeds them, and will supply document-level precedent to the Chief Engineer Agent once phase 2 is switched on.

Screen 8

Chief Engineer Agent

The decision-making agent. Runs the six steps above for every new query, and is the only service that talks directly to the local LLM to author a reply.

Q

Answer-quality scoring — RAGAS

Yes, this is still in the codebase and running: every historical-document search the History Retriever Agent performs is automatically scored with the RAGAS framework — faithfulness (does the retrieved text actually support the answer?) and answer relevancy — and the scores are logged for quality monitoring. It isn’t connected to the live vendor-query path yet, because that path doesn’t call the History Retriever Agent until step 2 above is activated in phase 2. Reconnecting RAGAS scoring end-to-end is part of that same phase-2 activation.

05

Confidence Scoring & Response Strategy

Confidence isn't a separate opinion from the AI — it is the similarity score between the new query and the closest matching past query. That single number then decides how much liberty the AI is allowed to take when writing the reply.

Confidence bandStrategyWhat the officer sees
≥ 0.95Verbatim reuseThe prior answer, presented as a ready-to-approve draft.
0.80 – 0.95ParaphraseOne strong precedent, reworded to fit the new question’s wording.
0.70 – 0.80SynthesisDraft blended from more than one related past answer.
0.50 – 0.70Context‑informedDraft generated from thin evidence — visibly caveated, review recommended.
< 0.50ExcludedNo precedent used; routed straight to manual drafting.

07

Human-in-the-Loop Governance

A query's status is a visible, auditable trail from submission to publication — nothing skips the review gate.

pending → under_review → answered  or → clarification_needed
●

Reuse a prior decision, not just the AI draft

The review screen shows the matched historical query, its confidence score, and its source document alongside the AI's draft. The reviewing officer can accept the draft as-is, edit it, or discard it in favour of a different historical precedent they judge more appropriate — the AI narrows the search, the officer makes the call.

08

Design Patterns Applied

Rather than a general-purpose autonomous multi-agent framework (LangGraph, CrewAI, AutoGen), this system uses a small number of purpose-built Python services orchestrated by direct, auditable code — each step is inspectable and logged. For a tender-compliance workflow, explainability took priority over agent autonomy.

Retrieval-Augmented Generation

The LLM never answers from memory. It is only allowed to write a reply after retrieving grounding evidence from the vector store.

Confidence-Tiered Generation

The retrieval score directly controls how much the model may author versus reuse verbatim — a graduated hand-off from precedent to synthesis to human judgement.

Human-in-the-Loop Review Gate

Every AI output lands in under_review before it can reach a vendor; nothing auto-publishes.

Scheduler / Background Worker

Query submission and AI processing are decoupled by a polling scheduler, so vendor-facing screens stay fast regardless of AI load.

Service-per-Capability

Retrieval, drafting, and document ingestion are three independent Python services — each can be scaled, upgraded, or swapped (e.g. a different local or hosted LLM) on its own.

Shared Toolkit, Independent Agents

Both agents build on one common LangChain-based toolkit (embeddings, prompt templates, chunking) rather than calling each other directly — low coupling, consistent behaviour.
